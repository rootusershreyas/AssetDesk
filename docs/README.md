# AssetDesk documentation

Start with the [Agile delivery handbook](agile/README.md). It covers product
discovery, requirements, planning, design, implementation/review, testing,
feedback, release, operations and maintenance for the A/B/C team.

| Guide | Purpose |
| --- | --- |
| [Product brief](agile/PRODUCT_BRIEF.md) | Problem, goal, actors, ownership and boundaries |
| [IT/electronic device scope](DEVICE_INVENTORY_SCOPE.md) | Initial seven categories, extensibility and planned location/deployment |
| [Requirements](agile/REQUIREMENTS.md) | Functional/nonfunctional acceptance and permissions |
| [Backlog](agile/BACKLOG.md) | Prioritized story proposal, acceptance criteria and recorded work states |
| [Iterations](agile/ITERATIONS.md) | Planning/stand-up/review/retrospective records, Ready/Done and Git policy |
| [Design](agile/DESIGN.md) | Architecture, data relationships, contracts and decision register |
| [Testing](agile/TESTING.md) | Story-to-test traceability, commands, evidence and complete demo |
| [Release](agile/RELEASE.md) | Current run commands, release gates, recovery and handoff |
| [Maintenance](agile/MAINTENANCE.md) | Defects, feedback, risks and scope-change records |
| [B database](B_DATABASE.md) | PostgreSQL setup, migrations and transaction contract |
| [B implementation](B_IMPLEMENTATION.md) | Asset file/function walkthrough and API examples |
| [B acceptance](B_ACCEPTANCE.md) | B-specific stories, manual checks and A/C handoff |

The full-product documents distinguish intended behavior from the implemented B
increment. Each owner updates their evidence with their PR. Framework/cadence,
business reviewer, operator and final acceptance still need real team records.
